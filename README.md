# Labestra

Учебный прототип для работы с научными статьями:

- **J1:** вопрос → план → поиск → выбор источников → сохранённый корпус.
- **J2:** вопрос и корпус → поиск и чтение фрагментов → ответ с claims/evidence → проверка.

**Для проверки КТ3:** [порядок проверки, результаты и соответствие требованиям](docs/SUBMISSION.md).
Основной документ проекта — [design_doc.md](design_doc.md), решение об архитектуре —
[ADR-001](adr/001-fixed-workflow.md).

Реальный system-прогон содержит все 24 visible-задания: 22 completed и
2 needs_clarification. По подтверждённым оценкам приняты 5 из 10 ответимых J2;
это отдельная метрика от технического завершения. Ручной B0 ещё не завершён,
поэтому сравнение качества и экономия времени относительно B0 не заявляются.

## Проверка без API и оплаты

Python 3.11+ со встроенным SQLite FTS5, macOS/Linux; на Windows — WSL.
Сторонние Python-пакеты и Docker не нужны.

```bash
./run.sh check
./run.sh scenarios --output runs/local/scenarios.json
.venv/bin/python -m labestra.submission
```

Первая команда создаёт `.venv`, проверяет данные и запускает тесты. Вторая
сохраняет шесть многошаговых сценариев. Третья пересчитывает качество сохранённого
system v2 и согласие разметчиков из файлов, без вызовов модели. Отчёты появляются
в `runs/local/submission-check/`. Наличие этих отчётов не заменяет ручной B0.

Технический пример цепочки на dev с подставными ответами:

```bash
.venv/bin/python -m labestra.workflow_demo
```

## Ручной baseline и модель

[Инструкция ручного B0](docs/MANUAL_B0.md): поиск и чтение те же, что у system,
ответ готовит человек без LLM. Для него не нужен API-ключ.

Для нового вызова модели:

```bash
./run.sh configure
# Заполнить configs/local.live.json по инструкции docs/WORKFLOW.md
./run.sh system --participant YOUR_NAME --case-id dev-01 --case-id dev-04 --session-id live-pilot
```

Конфиг принимает адрес OpenAI-совместимого API, ID модели, тариф и бюджет.
Ключ вводится скрыто или передаётся через `LABESTRA_API_KEY`; в Git не сохраняется.
`.env` автоматически не загружается. Если настройки не заполнены, запрос не выполняется.
[Конфиг сохранённого v2](configs/arkady.deepseek-v4-flash-0731.v2.json) опубликован без ключа.
Стоимость в отчётах справочная: фактический счёт прокси не подтверждён.

## Где что находится

| Путь | Содержимое |
|---|---|
| `labestra/` | общий runner, workflow, поиск, модель, Runtime и оценивание |
| `dataset_tools/` | подготовка, проверка и заморозка данных, согласие меток |
| `data/` | 30 источников, 240 фрагментов, корпуса и manifest с хешами |
| `eval/dev/`, `eval/visible/` | 6 dev и 24 visible; входы без gold |
| `eval/review/` | проверенные эталоны, пакет и подтверждённые оценки |
| `runs/submission/reports/` | итоговые отчёты оценки и согласия |
| `runs/submission/live-20261124-v2/` | полный v2 и все прежние попытки в архиве |
| `tests/`, `prompts/`, `configs/` | тесты, тексты промптов и настройки |
| `docs/archive/` | прежние планы команды; не актуальные инструкции сдачи |

Holdout остаётся приватным до КТ4. `runs/local/`, `.venv`, локальные конфиги,
ключи и SQLite-индексы исключены из Git. Исторический
`ai4s_mvp_architecture_v3_python.md` сохранён без изменений; актуальный объём MVP
и экспериментальная методика описаны в design doc.
