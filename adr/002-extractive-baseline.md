# ADR-002: автоматический baseline без LLM

| Поле | Значение |
|---|---|
| Статус | принят |
| Дата | 26.11.2026 |
| Авторы | Команда Labestra |
| Связано | [Design doc, §7–8](../design_doc.md#7-eval-план), [реализация](../labestra/baseline.py) |

## Контекст

Для сравнения с LLM-системой нужен простой baseline без генерации, работающий
с теми же заданиями, корпусами и поисковым движком. Ручной вариант требовал
чтения источников, выбора фрагментов и оформления ответа для каждого задания.
Это затрудняло повторные прогоны. Автоматический поиск и извлечение цитат
позволяют воспроизводить сравнение без ручного прохождения.

## Рассмотренные варианты

| Вариант | Качество | Задержка | Стоимость | Сложность и риски |
|---|---|---|---|---|
| Ручной поиск и ответ | Человек может синтезировать выводы; замеров нет | Зависит от чтения и подготовки ответа | API 0, требуется время человека | Зависимость от проверяющего и условий прохождения |
| BM25 и дословное извлечение | Проверяемые цитаты, слабый синтез и отказ | Локальный поиск и обработка текста | API 0; локальный CPU | Можно воспроизвести; релевантность слов не гарантирует полноту |
| Генеративный ответ без инструментов | Возможен связный синтез | Зависит от модели и процесса | Зависит от API | Не позволяет отделить вклад генерации |

## Решение

Использовать extractive-v1: тот же FTS5/BM25, английский search_query и заданные
корпуса. J1 выбирает первые 3 работы; исходный ranking до 20 сохраняется. J2
читает те же поисковые фрагменты и выбирает до 3 цитат длиной до 600 символов:
ранжирование по пересечению терминов и IDF, сначала по одной на источник.
Политика едина для всех заданий, gold решателю недоступен. Пустой запрос даёт
уточнение, отсутствие совпадений — insufficient_evidence. Остальные бюджеты
сохраняются из того же config, что у system v2.

## Последствия

- **Плюсы:** полностью автоматический воспроизводимый прогон, реальные измерения,
  ссылки на точные фрагменты, отсутствие модельных вызовов и затрат API.
- **Минусы:** нет перевода и смыслового синтеза; цитата может не отвечать вопросу.
  Ручная проверка полноты и принятия не заменяется совпадением текста с источником.
- **Проверка:** 24 одинаковых задания, общий runner и config; архив результатов,
  длительность, расход и парное сравнение сохраняются вместе с метаданными.
- **Условия пересмотра:** если baseline не отвечает на существенную часть прямых J2,
  после разбора ошибок сравнить другой детерминированный extractor на dev. Новая
  версия метода оценивается отдельным прогоном.
