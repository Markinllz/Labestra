## Подключение и проверки

Основа реализации: [PR #4](https://github.com/Markinllz/Labestra/pull/4),
`d9cc92def93b1a0857e6c582085ce0f94eb91a7b`. Он пока не слит в `checkpoint-3`.
Ветка данных основана на этой версии. Сначала интегрировать PR #4, затем изменения
данных. Общие `schemas.py`, `data.py`, `search.py`, runner и workflow не изменены.
КТ3 следует локальному процессу из `design_doc.md`, а не двухконтейнерному AI4S MVP.

Python 3.11+, без сторонних Python-зависимостей. Из корня:

```bash
python3 -m dataset_tools.validation
python3 -m unittest discover -s tests -v
```

Публичная проверка работает без `eval/private/`, без сети и без LLM. Она проверяет
ID, хеши, координаты, provenance, алиасы и совместимость с загрузчиками Макса.
Она **не подтверждает научную корректность** утверждений.

Runner получает `collection_id` из `data/manifest.json` и сверяет его с активным
config. В общем `configs/default.json` поле по-прежнему `null`: участнику 4 нужно
задать `labestra-retrieval-2026-11-v1` в конфигурации прогона. Не подменять `question`
английским запросом: для поиска уже задан отдельный `search_query`.
Непустые filters и фильтр года не используются.

```python
import json
from pathlib import Path
from labestra.data import load_sources, load_fragments, load_cases, load_corpora
from labestra.search import LocalSearch

root = Path('.')
manifest = json.loads((root / 'data/manifest.json').read_text())
tools = LocalSearch(
    sources=load_sources(root / 'data/sources.jsonl'),
    fragments=load_fragments(root / 'data/fragments.jsonl'),
    collection_id=manifest['collection_id'],
    config={'top_k': 20, 'timeout_seconds': 30},
)
case = load_cases(root / 'eval/dev/tasks.jsonl')[3]
corpora = {c.corpus_revision_id: c for c in load_corpora(root / 'data/corpora.jsonl')}
corpus = corpora[case.corpus_revision_id]
hits = tools.search_fragments(case.search_query, corpus)
exact = tools.read_fragments([f.fragment_id for f in hits], corpus)
```

## Происхождение и воспроизводимость

`data/catalog.json` содержит выбранные ACL ID. `sources.jsonl` соответствует
схеме 1.1; DOI взяты со страниц издателя, а не придуманы из названий.
`provenance.jsonl` содержит авторов, дату, URL, время получения, лицензионное
основание, отдельные хеши оригинального PDF/HTML и подготовленного текста.
В `aliases.json` можно явно связать DOI и OpenAlex одной работы. Пустой список
означает отсутствие проверенных дополнительных алиасов, а не отсутствие работы
в OpenAlex. SHA текстового снимка нельзя называть SHA PDF.

Тексты принадлежат авторам и ACL. Указанные материалы опубликованы после 2016 года;
основание повторного использования: [политика ACL](https://aclanthology.org/faq/#what-is-the-copyright-for-materials-in-the-anthology),
CC BY 4.0. Атрибуция хранится в sources/provenance. PDF преобразован командой
`pdftotext -enc UTF-8 -nopgbrk`, аннотация извлечена из блока `acl-abstract` HTML.
Смысл текста не переписывался. PDF, формулы и таблицы могут иметь несовершенный
порядок извлечения; существенные числа нужно сверять с оригинальной страницей.
Проверены визуально Table 2 DPR, PDF page 5, и Table 1 EntityQuestions, PDF page 1.
Это проверка подготовки данных агентом, не независимая человеческая разметка.

Нарезка Макса: 300 слов, overlap 50; точные Unicode-координаты. При изменении
байтов или нарезки меняются ID. Нельзя переносить старый gold на новые ID автоматически.
`manifest.json` охватывает входы solver; `release.json` дополнительно фиксирует
provenance, каталог, алиасы и описание набора. Изменение файлов требует новой версии.
В версии 0.1.1 уточнён только dev-запрос о технических вкладах RocketQA после
проверки dev-выдачи. Оба ответимых J2 dev-кейса возвращают эталонные фрагменты
в пределах поиска Макса. Это проверка доступности evidence, не научная оценка.

Для нового экспорта с сетевым доступом и установленным Poppler:

```bash
python3 -m dataset_tools.acquire --catalog data/catalog.json --output /tmp/labestra-new --cache runs/local/acquisition-new
```

Загрузка не выполняется при обычном тесте. Повторный экспорт в уже существующий
sources.jsonl запрещён. Свежий сайт или другая версия Poppler могут дать другие
байты: авторитетны сохранённые снимки и их хеши, а не обещание повторить загрузку.

## Приватные эталоны

Локально у хранителя находятся `eval/private/gold/{dev,visible,holdout}.jsonl`,
`holdout/tasks.jsonl`, `holdout/corpora.jsonl`, `manifest.json` и пакет разметки.
Они исключены из Git; рабочая папка private имеет режим 700.
Это не защита от коллег с доступом к тому же пользователю ОС. Передавать им
только публичный checkout. Приватный комплект нужно отдельно сохранить у Аркаши;
из клона Git он не восстановится.

```bash
python3 -m dataset_tools.validation --private eval/private
python3 -m dataset_tools.validation --private eval/private --require-reviewed
```

Вторая команда сейчас **должна завершаться ошибкой**: все 42 эталона являются
черновиками. `reviewed_by` пуст, метки людей не сгенерированы. Проверка требует
двух разных проверяющих, отличных от автора, но не может удостоверить их личность.
Нельзя просто заполнить имена ради прохождения проверки.

J1 gold: весь candidate pool, relevant IDs, отдельное решение и объяснение по
каждой работе. J2 gold: действие, корпус, атомарные claims, условия (`task`,
`dataset`, `method`, `comparison`, `metric`, `scope`), допустимые перефразы и exact
quotes с fragment ID. Отсутствие оснований задаётся действием
`insufficient_evidence` и ограничением; пустой ответимый gold отклоняется.

Приватный manifest связан с хешем публичного. Изменения gold требуют новой
приватной версии; изменения источников требуют пересмотра ссылок и нового seal:

```bash
python3 -m dataset_tools.freeze --private eval/private --version 0.2.0-draft
```

Зафиксированный SHA-256 текущего приватного manifest:
`2073cb0de857df45387de8aac4c35ef82d180d87659f2225c2fb3339b2f41e07`.
Это обязательство о конкретных байтах, не доказательство их научной корректности.

## Независимая разметка

Заранее выбраны J1 `visible-01/04/07/11` и J2 `visible-13/17/18/22`.
Пакет `eval/private/review/packet.json` содержит 139 объектов и не раскрывает
первичные метки, expected_action, relevant IDs или rationale автора.
В пары включены также кандидатные утверждения для проверки противоречия и
недостатка данных; их истинность не предполагается. Два пустых файла
`ann_1.jsonl` и `ann_2.jsonl` содержат одинаковые object IDs и хеш пакета.

1. Каждый человек независимо заполняет свой annotator_id, label и rationale.
2. Не смотреть файл другого человека до сохранения исходной версии.
3. Рассчитать согласие отдельно для action, relevance, entailment:

```bash
python3 -m dataset_tools.review agreement --packet eval/private/review/packet.json --first eval/private/review/ann_1.jsonl --second eval/private/review/ann_2.jsonl
```

4. Сохранить исходные метки; обсуждать расхождения отдельно. Согласованный gold
создаётся новой версией. Не заменять исходные метки согласованными.
5. Перед официальной оценкой проверить весь gold, не только эти восемь кейсов.
Согласие по восьми кейсам не подтверждает качество остальных.

Пустые, несовпадающие по объектам или версии метки отклоняются. При постоянных
метках Cohen's kappa возвращается как неопределённая, а не 1. Расчёт не принимает
два файла одного annotator_id за независимую проверку.

Рубрика: вывод должен сохранять метод, датасет, режим обучения/оценки, baseline,
метрику и предел применимости. `supports` означает, что фрагмент поддерживает
утверждение с этими условиями; `contradicts` означает несовместимый результат
при сопоставимых условиях; `uncertain` означает, что связи недостаточно.
Разные модели или разные датасеты сами по себе не образуют противоречия.
Объяснение причины расхождения требует отдельного evidence. Пример риска:
в DPR есть исключение SQuAD, поэтому формулировка «dense всегда лучше BM25»
не допускается. Точная ссылка без правильного смысла проверку не проходит.

Gold не передавать авторам B0 до записи их ответов. Holdout не передавать
разработчикам до КТ4. Формат итоговых оценок и официальные метрики остаются
ответственностью участника 4; здесь вычисляется только межэкспертное согласие.
