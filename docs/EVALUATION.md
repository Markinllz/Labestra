# Методика и результаты оценки

## Варианты

**System v2:** фиксированный J1/J2, BM25/FTS5, DeepSeek-V4-Flash-0731 через
OpenAI-совместимый API. В J1 после поиска предусмотрен выбор источников,
в J2 — структурированный ответ с claims/evidence.

**Extractive-v1:** тот же поиск, запросы и корпуса без LLM. J1 сохраняет первые
3 статьи; J2 возвращает до 3 цитат по пересечению терминов и IDF, сначала по одной
на источник. Цитата — непрерывный отрезок до 600 символов исходного фрагмента.
Пустой поисковый запрос вызывает уточнение; отсутствие совпадений — отказ.
Смысловой проверки, перевода и синтеза в baseline нет. [ADR-002](../adr/002-extractive-baseline.md).

Решатели не получают gold или оценки. Для обоих вариантов используется один
runner, одни 24 visible-задания и побайтно одинаковый config v2. Seed API не
поддерживается; temperature=0, версии и хеши промптов/данных сохранены в manifest.

## Воспроизведение

```bash
./run.sh check
./run.sh scenarios --output runs/local/scenarios.json
.venv/bin/python -m labestra.submission
```

Последняя команда распаковывает сохранённые сессии и пересчитывает отчёты без
модели и оплаты. Она проверяет идентичность вопросов, запросов, корпусов, config
и gold при парном сравнении. Вывод — `runs/local/submission-check/`.

Новый реальный baseline:

```bash
./run.sh baseline --config configs/arkady.deepseek-v4-flash-0731.v2.json \
  --cases eval/visible/tasks.jsonl --session-id baseline-new
```

Для прямого CLI укажите `--variant baseline --baseline-policy extractive-v1`.
Старый ручной режим остаётся доступен как `--baseline-policy manual`, но не
используется в текущих числах.

## Интерпретация

BM25 одинаков у обоих вариантов: улучшения retrieval не обнаружено. Качество
выбранного корпуса различается, но system включает внешний отбор статей;
это свойство всего workflow. Baseline пропустил одну из двух нужных работ в
visible-07, выбрав только первые 3 кандидата. На visible-23/24 baseline выдаёт
цитаты вместо требуемого отказа. У system неверные действия — visible-13/20:
недостаток оснований на ответимых вопросах.

System принят в 5 из 10 ответимых J2, ниже цели 70%. Ошибки полноты остаются
в visible-17/21/22; в visible-20 отдельная связь не подтверждает заявленный вывод.
Наличие корректного fragment_id проверяется кодом и не заменяет entailment.
Неоценённые смысловые метрики baseline — `null`, а не ноль и не 100%.

## Проверка смысловых оценок

```bash
.venv/bin/python -m labestra.review_ui \
  --session runs/local/baseline-new --gold eval/review/gold.visible.jsonl \
  --output runs/local/baseline-review.html
```

Форма содержит вопрос, ответ, основания и обязательные выводы. Оценки исходно
пусты; экспорт доступен после явного подтверждения всех 12 кейсов. Полученный
JSONL проверяется тем же scorer:

```bash
.venv/bin/python -m labestra.submission \
  --baseline-ratings /path/to/baseline-ratings.jsonl
```

Рейтинги должны покрывать каждый claim, каждую связь и все проверяемые J2.
Идентификатор проверяющего отличается от оператора решателя. Это проверка
записей; сама по себе она не доказывает независимость процедуры.

## Разметка и ограничения

Мы сохранили подтверждённые исходные метки по 139 объектам из 8 кейсов и
рассчитали согласие до согласования: action 8/8 (κ=1), entailment 11/11 (κ=1),
relevance 119/120 (κ≈0,9808). Расхождение — metadata-only источник
acl:D16-1264 в visible-07. Полная независимость и слепота не установлены;
числа описывают совпадение меток, а не независимый потолок качества.

Первоначальный ручной B0 не завершён и заменён extractive-v1. Новый метод выбран
после просмотра visible system; параметры едины для всех кейсов и зафиксированы
до сохранённого прогона. V2 самой системы также пересмотрен после сбоя на visible.
Это описательное сравнение, а не новая нетронутая выборка. Данные и gold под
результаты не менялись; holdout не открывается до КТ4.

Стоимость system рассчитана по справочному тарифу; фактический счёт прокси не
подтверждён. Две старые попытки имеют неизвестный usage. Все прежние попытки
сохранены; текущая сессия не собрана из лучших ответов разных запусков.
