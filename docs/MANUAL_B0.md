# Ручной B0

B0 — человек с тем же поиском и чтением, что у системы. Модель не вызывается.
Результат, время, действия и причины остановки сохраняет общий runner.
Подставить заранее подготовленные ответы и выдать время ввода за время решения нельзя.

## Перед запуском

1. Закрой gold, чужую разметку и ответы системы. Во время прохождения используй
   только вопрос, результаты поиска и чтение через runner.
2. На 26 ноября эталоны и оценки уже подтверждены Сабухи. Для его запуска
   используй `--prior-reference-access`: это ручное прохождение после просмотра
   эталонов, со следом в manifest. Повтор не восстанавливает слепоту.
   Если другой участник действительно не видел материалов, ему доступен
   `--blind-attestation`. Эти флаги несовместимы.
3. Не меняй вопросы, корпус, поиск и config v2. На задание выделено 240 секунд
   человеку и 300 секунд всего. Ошибки и отказы также входят в результат.
4. Запусти `./run.sh check` из корня проекта.

## Пилот: два dev-задания

```bash
./run.sh baseline \
  --config configs/arkady.deepseek-v4-flash-0731.v2.json \
  --participant sabukhi --prior-reference-access \
  --case-id dev-01 --case-id dev-04 --session-id b0-manual-pilot
```

`session-id` должен быть новым: старые результаты не перезаписываются.

## Как отвечать

**J1 — выбрать статьи.** Прочитай вопрос. Введи `read 1,2`, чтобы прочитать
фрагменты первой и второй работ. Затем введи номера выбранных работ через запятую,
например `1,3`. Это только пример синтаксиса, не правильный ответ задания.
Выбирай по содержанию, а не по месту в выдаче.

**J2 — ответить по корпусу.** Runner показывает найденные фрагменты. Сначала выбери,
достаточно ли информации: `1` — достаточно, `2` — недостаточно,
`3` — нужен уточняющий вопрос. Для ответа:

1. Напиши ответ своими словами. Заверши ввод отдельной строкой с точкой `.`.
2. Укажи количество отдельных проверяемых выводов.
3. Для каждого напиши текст, заверши точкой и выбери номера подтверждающих фрагментов.
4. Укажи отношение: подтверждает, противоречит или связь неясна.
5. Укажи ограничения либо введи только точку.

Не нужно вручную писать JSON или длинные ID: runner собирает структуру сам.
Если факта нет в доступных источниках, так и напиши. Наличие ссылки само по себе
не означает, что она подтверждает вывод. `/cancel` и Ctrl-C сохраняют остановку.

## Visible: 24 задания

После пилота:

```bash
./run.sh baseline \
  --config configs/arkady.deepseek-v4-flash-0731.v2.json \
  --participant sabukhi --prior-reference-access \
  --cases eval/visible/tasks.jsonl --session-id b0-manual-visible
./run.sh pack --session runs/local/b0-manual-visible --output runs/b0-manual-visible.zip
```

Не открывай эталоны во время сессии. Сохраняем все попытки, а не лучший ответ
на каждое задание. При прерывании не переиспользуй session-id. Для продолжения
нужны только ещё не пройденные case-id в новой сессии; сессии нельзя молча склеивать
или исключать неудачные попытки из знаменателя.

## После прохождения

```bash
.venv/bin/python -m labestra.submission \
  --baseline-session runs/local/b0-manual-visible \
  --output runs/local/paired-check
```

Эта команда посчитает исполнение, ресурсы, действия и поиск. Для смыслового
сравнения J2 нужны оценки claims/evidence с сохранённым именем проверяющего;
собственные ответы не выдаются за независимо оценённые. Экономия человеческого
труда не выводится из текущего system v2: его время взаимодействия не является
замером работы человека. Ограничение предварительного просмотра gold указывается
в итоговом сравнении; оно не устраняется выбором другого флага.
