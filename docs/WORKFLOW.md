# Workflow и интерфейсы

## Выполнение

Один Python-процесс загружает и проверяет набор, создаёт `LocalSearch` и общий
`Runtime`, затем передаёт их в `WorkflowServices`. Внутреннего HTTP API нет.
Внешняя сеть используется только адаптером модели.

**J1:** непустой query → план → подтверждение → поиск → выбор → CorpusRevision.
**J2:** заданный корпус → поиск → чтение точных ID → генерация → проверка схемы.
Изменение вводных отменяет старый черновик и возвращает процесс к поиску.

`baseline.py` реализует extractive-v1 с теми же инструментами и `RunResult`.
Он не создаёт модель и не обращается к эталонам. Политика и параметры цитат
сохраняются в manifest и событиях.

## Контракты инструментов

```python
search_sources(query: str, filters: dict[str, str], collection_id: str) -> list[Source]
search_fragments(query: str, corpus: Corpus) -> list[Fragment]
read_fragments(fragment_ids: list[str], corpus: Corpus) -> list[Fragment]
```

Поиск использует готовый английский query; перевода и переформулирования нет.
Фильтры в текущей коллекции не поддерживаются. Выдача — до 20 источников,
до 10 фрагментов с ограничением 3 на источник. Порядок фиксируется до выбора.
`read_fragments` проверяет принадлежность корпусу и возвращает точный текст.

Ошибки: `ToolFailure(ToolError(code, message, retryable, tool_call_id))`.
Инструмент задаёт code/message/retryable, обёртка добавляет фактический call ID.
`invalid_input`, `not_found`, `outside_corpus`, `timeout`, `io_error` не заменяются
произвольной строкой. Поиск контролирует timeout SQLite; Runtime — общий deadline.
Временная ошибка допускает до 2 повторов, кроме случая неизвестного расхода API.

## Бюджеты

Сохранённый v2: до 20 действий, 10 LLM-вызовов, 5 поисковых, 100k/30k суммарных
входных/выходных токенов; 300 с и 0,10 USD на задание. Лимит сессии 0,80 USD.
На вызов — до 32k входа/12k выхода, окно 48k, LLM timeout 180 с.
Поиск/чтение — 30 с. Один repair JSON разрешён на весь запуск.

При исчерпании — `budget_exceeded`, новые действия запрещены. При отмене
поздний ответ не публикуется. Неизвестный usage останавливает платную сессию
без автоматического повтора. Отмена ожидания не гарантирует отмену списания
у провайдера. Baseline имеет нулевой расход LLM, но использует те же бюджеты
инструментов и времени.

## Подключение API

`LanguageModel.complete(messages, ...)` возвращает текст, usage и версию модели.
Доступны `ChatModel` для HTTPS OpenAI-compatible API и `YandexModel` для
Yandex completion API. `FixtureModel` используется только в технических тестах.

`./run.sh configure` создаёт локальный конфиг без ключа. Обязательные настройки:

- `model.base_url`, `model.model_id`, `model.provider`, формат API;
- `pricing`: валюта, тарифы за 1000 токенов, дата и источник;
- `limits.max_cost`, `limits.currency`, `session_max_cost`;
- контекстное окно, входной/выходной лимиты и проверенная оценка токенов.

`token_bound_verified` выставляется после проверки tokenizer/формата запроса.
До заполнения параметров live-запуск блокируется. Ключ — `LABESTRA_API_KEY`
или скрытый ввод; он не передаётся в аргументах CLI и не сохраняется в config.
HTTP-редиректы и неявные повторы адаптера запрещены. Усечение ответа сохраняет
известный usage и завершается ошибкой.

## Результаты

Каждое задание сохраняет `input.json`, `config.json`, `result.json`,
`manifest.json`, `events.jsonl`, `corpora.json`; сессия — `summary.json`.
Manifest включает хеши кода, данных и промптов, Python/SQLite, модель,
параметры, политику baseline и предупреждения подготовки.

Запись атомарна. Идентичный повтор публикации не создаёт дубль; другой результат
по занятому ключу отклоняется. Новый CLI session-id нужен для нового запуска.
`runs/local` исключён из Git; `./run.sh pack` упаковывает только артефакты runner.
